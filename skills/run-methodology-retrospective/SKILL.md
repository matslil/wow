# Run a Methodology Retrospective

For a work-package lead or reviewer in any work type, read the project definition,
affected delivery evidence, and [the workflow](../../workflows/methodology-retrospective.md).
Evaluate context efficiency, result quality, and human communication. Separate
observations from causes inferred from them. Keep recommendations scoped to the
evidence rather than accumulating universal rules.

Output a concise outcome, decisive evidence, local actions, knowledge changes,
skill proposals, and any human decision required. Use the retrospective/proposal
templates only when they help. Store durable findings in scoped knowledge.

Validate each proposal against a realistic task and affected authority rules.
Record `pass`, `fail`, `inconclusive`, `not-applicable`, or `pending-human` with
limitations. Human acceptance is required for all skill changes; external feedback
submission also needs explicit authorization. Continue independent authorized work.
