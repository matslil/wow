# Story-Based Work

Use for novels, books, roleplaying adventures/rules, and other narrative work.
Follow the shared core and [develop-story](skills/develop-story/SKILL.md).
Engineering lifecycle rules apply only to engineering parts of a mixed project.

Keep the intended audience, experience, scope, and author constraints discoverable
from root goals. Store canon, character descriptions, timelines, outlines, and
research in the owning module's `knowledge/`; story text is implementation.
Use one authoritative canon and link cross-module dependencies.

[Craft guidance](knowledge/guidelines.md) is advisory. Apply relevant defaults
unless a deliberate exception better serves the work; no guideline is a hard
requirement or automatic rejection criterion. Distinguish human constraints from
editorial preferences. A checklist cannot establish artistic quality.

Maintain root `AI-USAGE.md` with the provenance of individual chapters/sections
where needed: human-only, human/AI collaboration and its exact form, or AI-generated.
Validation-only and grammar/spelling assistance must remain distinguishable from
AI drafting. Unknown prior authorship stays unknown. Use the
[shared template](../templates/AI-USAGE.md).

For interactive stories, verify state and paths and validate meaningful choices.
For tabletop work, playtest rules and adventure usability with participants when
possible; disclose when only a desk review was available. Software tooling also
uses the engineering checks applicable to that software.
