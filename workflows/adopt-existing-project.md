# Adopt an Existing Project

1. Inventory the deliverable, existing knowledge, instructions, provenance,
   licenses, checks, and human authorities. Read the root purpose first.
2. Identify work types and scope: engineering, story, or a combination. Reuse
   existing authoritative artifacts and paths; do not create competing copies.
3. Mark evidence, inference, unknowns, and conflicts. Create a provisional project
   definition and tailoring record; ask only questions repository evidence cannot
   resolve. Obtain human confirmation for inferred intent and authority.
4. Choose a shared module tree or separate work-type trees based on dependencies.
   Add general `skills/` and `knowledge/` indexes and scoped equivalents as useful.
5. Plan requested adoption items using the shared workflow: one PR per item,
   verified commits pushed individually, PR opened when that item's plan is done.
   Propose a breakdown for large migrations; do not silently multiply requested PRs.
6. Summarize knowledge changes, propose skill changes for human acceptance, document
   AI use without guessing history, and validate representative existing tasks.

Engineering projects additionally map lifecycle/model evidence and human tollgates.
Stories map canon, intended reader experience, editorial checks, and provenance.
Preserve valid evidence; introduce missing artifacts incrementally within scope.
